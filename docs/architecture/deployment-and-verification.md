# 作品展示网站部署与验证方案

版本 1.0 · 2026-10-27 · 简化首期。配套[技术主方案](../superpowers/specs/2026-10-27-portfolio-technical-design.md)和[接口契约](data-api-contract.md)。以下为待执行计划，不是已部署或已测试结果。

## 1 一台服务器运行

先用一台服务器运行 Nginx、Next.js、Java API、PostgreSQL 四个容器。2 vCPU、4 GB 内存可作为试运行起点，Java 堆初值 1536 MB、Node 内存上限初值 512 MB，数据库缓存初值 256 MB；总进程内存和真实大图必须实测，不以这些数值承诺并发能力。

只公开 80、443，其他进程走内部网络。数据库和图片目录挂持久卷，容器重建不删除。图片使用独立挂载目录 /data/media，数据库使用独立持久卷；备份存到服务器外。

访客地区、域名、具体机器和备份目的地后续确认即可，不影响当前模块和接口设计。没有购买或创建任何云资源。试运行先用测试素材，至少 3 个真实项目通过图片和布局检查后再准备正式内容。

## 2 路由与基础安全

| 路径 | 处理方式 |
| --- | --- |
| 公开与后台页面 | Next.js；业务 HTML no-store |
| /api/public/v1 | Java；读取当前公开快照 |
| /api/admin/v1 | Java；所有请求检查会话，写操作检查 CSRF |
| /api/auth | Spring Security 登录、退出、会话和 CSRF |
| /media | Java 查询当前公开引用后流式读文件，no-store |
| 静态哈希脚本与样式 | 可长缓存，不含草稿或密钥 |
| 数据库、健康管理、文件目录 | 不允许公网直接访问 |

生产使用 HTTPS。会话 Cookie 设置 Secure、HttpOnly、SameSite=Lax、Path=/；Java 单实例内存会话，空闲 30 分钟失效。重启会要求重新登录，不造成数据库已保存内容丢失。

唯一维护者用户名与 BCrypt 哈希通过私密环境文件加载，文件权限限制且不进 Git。部署时由维护者离线生成强密码哈希，不在聊天或仓库放密码；没有默认密码。密码修改更新配置后重启，不做注册、找回和第三方 OAuth 应用。

登录接口初值按来源 5 次/分钟、全站 30 次/分钟限速，并返回统一失败提示；业务接口保持参数化 SQL、纯文本渲染和 CSRF。只同源访问，不开放通配 CORS；可信代理覆盖 Forwarded 头。后台重登录不能把会话放入 localStorage。

前端服务端请求只向固定内部 Java 地址，不用访客 Host 构造目标；媒体路径由资源表映射，不直接拼接访客文件名。配置安全响应头防止内容嗅探与第三方嵌入，外链只接受 HTTPS 并使用 noopener。日志不记录密码、Cookie 和草稿正文。

## 3 上传与大图验证

文件本体严格限制 20 MB，multipart 请求上限可为 21 MB 以容纳协议开销。逐文件请求，前端默认串行，Java 全局图像处理并发 1；服务器忙时明确提示稍后再传，不排入持久任务。

处理失败或进程异常时，维护者可重传，必要时重启 Java 服务。HTTP 超时只是停止等待，不宣称已经硬中断 ImageIO 解码；不能因超时立即无限启动新处理。单并发许可在实际解码结束后才释放，进程异常以重启恢复。

真实素材必须验证：横竖 JPEG、透明 PNG、静态 WebP、带方向和色彩配置的图片；伪装扩展名、截断文件、SVG、动画 WebP、超过 20 MB、超 40 MP 和超单边限制的输入明确拒绝。低清晰度只提醒，不擅自拒绝。

原图和显示图不覆盖，显示图转 sRGB 并去元数据。透明素材不被强制转成黑底 JPEG。品牌图、包装文字和细线条用 3 个真实项目肉眼对照，避免缩图过度压缩。若 PNG 显示图偏大，先调整档位，不先加媒体转码平台。

首期不自动删服务器图片。无引用目录、重传产生的副本或失败临时文件，先备份再核对引用人工清理；上线初期可以先不清，观察磁盘容量。曾发布文件和回收区文件保留。

## 4 简单备份和恢复

每天夜间备份一次数据库，使用 pg_dump 自身的一致性快照；再复制完整媒体目录到机器外，并记录文件清单和摘要。由于文件不可变且不自动删除，数据库快照引用的原图不会在复制途中被覆盖或清理。备份包只有数据库与媒体清单核对完成后才标记成功。

保留最近 7 个日备份和 4 个周备份，存放在不依赖原服务器磁盘的位置。仅把文件放同机另一个目录不算外部备份。首次备份后必须核对公开快照、原图、显示图均在清单中；失败要能在每日检查记录中看到，不能静默忽略。

恢复步骤为：新建干净运行环境，恢复数据库和媒体目录，使用原有密码哈希配置重新启动，检查至少 3 个作品和配置，确认引用与公开状态后再切换访问入口。内存会话自然清空，无后台任务需要续跑。应用回退用上一镜像，数据库不自动执行破坏性逆向迁移。

初始恢复目标允许最多丢失 24 小时已保存内容，目标 4 小时内恢复。它们需要演练，不是当前 SLA。服务器故障期间允许短时不可用；首期不做主备切换和自动故障转移。

## 5 开发与验收次序

| 阶段 | 覆盖范围 | 完成标志 |
| --- | --- | --- |
| 1 基础闭环 | A00、A02、A03、C01 | 能登录、传图、保存草稿，容器重启不丢已保存数据 |
| 2 作品发布 | A01、A04、C02 | 草稿隔离、同步发布下架、回收恢复、重复请求不意外上线 |
| 3 配置分类 | A05、A06 | 设置发布、分类即时修改和引用检查、完整排序 |
| 4 公开页面 | G01–G02、W01–W03 | 真实数据筛选、详情、放大、返回与联系闭环 |
| 5 首页 | H01–H09、C03 | 九区块内容规则、手机布局、核心动效及静态降级 |
| 6 上线准备 | 全部 | 基本权限和故障验证、备份恢复、真实素材检查 |

技术方案确认后才写可执行开发任务和产品代码。阶段是开发组织建议，不是现在开始执行的指令。

## 6 必要的验证

| 场景 | 必须看到的结果 |
| --- | --- |
| 未登录请求后台、上传、预览和管理图片 | 拒绝，不改数据、不泄漏草稿 |
| 上传封面正文并保存草稿 | 后台可看，公开页、公开 API 与图片路径不能看到草稿 |
| 发布作品及首页配置 | 正确上线；首页不自动插入未选作品 |
| 已发布作品只保存新标题和图 | 公开完整保留旧版 |
| 发布中断、事务报错或响应丢失 | 只可能旧版或完整新版；刷新可确认；不产生半更新 |
| 发布后下架，再重放旧发布请求 | 状态冲突，不能重新上线 |
| 两个标签页保存同一版本 | 一个成功，另一个提示冲突，输入可复制保留 |
| 一张图失败或取消晚到 | 成功图不重传，取消项不自动绑定，允许存在无引用副本 |
| 从草稿移除公开仍使用的图 | 公开图片继续读取，首期没有自动删除任务 |
| 25 件作品连续加载并往返详情 | 12、24、25 显示；下架补足；新增重排不干扰原顺序 |
| 分类改名停用删除与迁移 | 改名即显示新名；停用保留旧关联；有当前引用不能删；迁移草稿不改线上 |
| 联系方式只保存后再发布 | 首页、关于、页脚先共同保留旧值，再共同切换 |
| 320、390、768、1440 宽度和减少动画 | 正文按钮无意外溢出，筛选放大联系不依赖动效 |
| 重启和外部备份恢复 | 已保存内容和媒体匹配，当前公开状态正确，重新登录可维护 |

对应原 E01–E12 的正常业务闭环仍保留。原 A04 的操作编号查询、A03 的持久上传恢复、C01 的自动清理等按主方案第 11 节收敛，不按旧文宣称原样实现。

前端动效另验：H01 卡片展开不挡点击，H02 少于 3 项降级，H03 两端焦点独立，H04 减少动画全文可读，H05 分类切换空态可用，H06 暂停后不继续移动且副本不聚焦，H07 下架案例移除，H08 无收费流程，H09 复制失败有可手动复制文本。

## 7 验证工具与规模检查

Java 单元测试验证字段规则，Testcontainers 使用真实 PostgreSQL 验证保存冲突、发布回滚、旧命令与下架竞争；浏览器测试覆盖主要管理和公开路径，截图核对关键宽度。不会为每个简单样式镜像编写测试，但权限和数据状态不能只靠目测。

性能先用真实 3 个项目测首页、详情与图片加载，再用 100 件作品检查列表和排序；接近 1000 件时重新检查全量编号浏览方式、查询体积和备份大小。上传 40 MP 素材时观察 Java 进程总内存和首屏可用性，不能只看 Java 堆配置。

运行观察先保留简单应用日志、磁盘容量、容器健康和每天备份成功记录，不部署完整监控平台。磁盘达到 80% 或重复上传失败时由维护者检查。按平均每件 10 张、每张 4 MB 估算，100 件原图约 4 GB，显示图和外部备份另计；最终按实际素材测量。

## 8 上线前待确认

- 部署地区、域名、试运行机器及外部备份目的地。
- 维护者用户名和由其保管的密码配置，不能提交到仓库。
- 至少 3 个真实项目、品牌名称、联系内容及最终分类。
- 接受单机维护、故障手工处理、重启后重新登录和不自动删图的首期边界。

这些不是要求现在购买服务。本轮文档评审不等于功能测试完成；技术方案确认后才进入开发。
