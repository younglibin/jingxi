# 作品展示网站技术方案评审记录

日期 2026-10-27。评审对象为[技术主方案](../superpowers/specs/2026-10-27-portfolio-technical-design.md)、[数据接口契约](../architecture/data-api-contract.md)、[部署与验证](../architecture/deployment-and-verification.md)。仅进行文档和逻辑评审，未开发或运行产品代码。

## 1 本轮结论

按小型作品网站范围收敛后的方案，可作为下一步开发计划的技术基线。独立评审未发现需要增加队列、租约、发布操作中心、独立图片服务或分布式组件的架构阻断。唯一发现的分类切换行为缺项已补入主方案和接口契约。

这不代表功能测试、性能测试或备份恢复已经通过。部署参数和图片处理结果仍需开发后验证。是否进入产品开发仍由用户确认，本轮只交付方案。

## 2 评审依据与方式

- 已评审需求：模块需求 v0.2、Figma V1.1 交付说明；用户本轮确认界面评审完成。
- 用户新增约束：简单网站，失败可以重启或重传，不要过度设计。
- 技术路线：按用户回复“2”解释为第 2 种技术路线，即前后端分离、Java 后端；已在会话中说明。
- 主设计者检查数据与文件边界、同步事务和原需求取舍；另一位独立评审者按“能否据此开始制定开发计划”检查重要缺项。
- 独立评审重点为重复发布、下架后旧请求、稳定列表、图片引用、内存会话与本地存图；没有要求真实部署或故障注入。

## 3 发现与处理

| 编号 | 问题或判断 | 处理 | 结果 |
| --- | --- | --- | --- |
| R01 | 初始技术展开过重，不适合当前网站规模 | 按用户指示改为同步上传与发布、进程内会话、本地文件、人工恢复；删除任务、租约、持久上传队列和第三方登录配置 | 已收敛 |
| R02 | 独立评审发现：切分类是否重建编号顺序和重置首批未写清，与原 W01 有偏差 | 主方案第 6 节和接口契约公开 API 节明确重新取 catalog、take=12、回到列表起点；详情返回继续恢复原上下文 | 已修正 |
| R03 | 重复发布如果直接“重新设为公开”，可能把已下架作品意外上架 | 固定判断顺序：仅当前仍公开的同源修订可无修改返回；其他情况必须校验 stateRevision；举例状态 10→11→12 后旧请求被拒绝 | 逻辑评审通过，开发时测竞争用例 |
| R04 | 重新上架复用快照时，原发布时间与本次上架时间可能混淆 | 增加 work.lastPublishedAt 表示本次主动发布；不可变快照 publishedAt 保留首次创建时间；重复请求不改时间 | 已明确 |
| R05 | Java 默认 ImageIO 没有完整的静态 WebP 支持，不能只检查后缀 | 指定 TwelveMonkeys WebP 读取插件；输出用 JPEG 或保留透明度的 PNG；真实格式和色彩素材实施时验证 | 选型明确，兼容验证待开发 |
| R06 | 只查当前引用表就清理文件，会误删历史快照图片 | 首期不自动删图；人工清理需备份并查历史快照；原图和显示图不可变 | 无需清理状态机 |
| R07 | 简化发布和恢复后仍保留旧文，会让开发者误认为需要操作中心 | 主方案第 11 节列出与旧需求的差异；仓库索引指向最新技术方案；旧归档不覆写 | 已说明范围 |
| R08 | 本地存图和单机部署容易把容器重建等同于持久化或备份 | 数据库与图片挂独立持久目录，每天机器外备份并至少演练一次 | 基本措施保留，演练待开发 |

## 4 关键逻辑检查

### 同步发布与下架

发布只处理数据库，文件已在上传阶段完成。公开快照、指针、引用、可见状态与审计同事务变更，失败回滚。重复同修订返回已有结果；下架提高状态版本，因此旧发布请求不能重新生效。独立评审认为不需要另建操作表与后台发布队列。

数据库进程或 Java 服务重启后，已提交事务完整保留，未提交事务回滚。未知响应由维护者刷新确认。这里接受人工操作，不承诺后台自动继续发布。

### 列表与分类

标签页保存初始公开编号顺序；服务端每次按当前公开状态与分类重新过滤，返回完整已加载前缀。新增和全局重排不插入当前顺序，下架可补足；分类迁移不会因只取下一批而产生重漏。

切换分类和刷新建立新顺序、重置首批；从详情返回保留旧顺序后重新验证。这个约定同时解决原需求与简化算法的衔接，不需要服务器浏览会话。

### 上传、会话和恢复

失败单图重传，取消晚到结果由当前浏览器队列忽略；允许少量未引用副本，不用持久任务去重。服务器资源只在校验与显示图完成后可绑定，发布不依赖未完成上传。

会话重启后丢失被明确接受；已保存内容和文件在持久存储中保留。后台只能唯一维护者访问，密码哈希不进仓库。文件不自动删除，保留机器外备份，避免把“简单”变成数据不可恢复。

## 6 实施前的范围确认

本轮保留浏览编辑发布闭环和关键视觉目标；操作编号查询、持久上传恢复、自动永久清理等按主方案第 11 节简化。开发估算以这版收敛范围为准，不能同时拿旧需求的自动恢复条目要求首期实现。

下一步是用户确认技术方案后拆开发任务；当前没有编写网站应用、安装依赖、购买资源或发布站点。
